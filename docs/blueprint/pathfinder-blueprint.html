PATHFINDER — 비전공자 바이브코더의 컴퓨터에 상주하며 먼저 말을 거는 오픈소스 비서. 이 문서는 구조를 코드보다 먼저 합의하기 위한 것이다. 숫자는 전부 Mark.5 실측과 조사 7건에서 나왔다.

v3 에서 바뀐 것 — "한 단계 멀리"로 v2 의 축소를 다시 걸렀다

대표의 원칙(D8): PATHFINDER 는 문제 해결 도구가 아니라 실질적인 AI 비서다. "아직 쓰임이 없다"만으로 비서다움에 직결되는 능력을 자르지 않는다. v2 가 걷어낸 스물을 이 눈으로 다시 봤다.

되살린 것 — 임베딩과 벡터 색인(D10) · 턴 도중 사용자의 말을 반영하는 steer(D12) · 예약 신호(아침 브리핑 · "내일 9시에 알려줘" — 비서의 기본기) · 새 검증 도구를 하루 한 번 확인하는 catalog 감각(능동 제안의 계기가 없으면 제품의 핵심 문장 "지금 하시는 작업에 이런 도구가 나왔습니다"가 성립하지 않는다).

그대로 걷어낸 것 — 역할 다섯(D9) · 코드 모드 우선(D11) · 말 걸기 분류 · meter 모듈 · 낮/밤 두 통과 · SCHEMA.md · notes/ · skills/(D58 · D61 로 되살림 — 대표가 승인한 절차를 모은 폴더 하나) · 설정 파일 둘 · 참조 서버 · 공유 렌더 층 · 에이전트 여섯. 이것들은 없어도 비서 경험이 줄지 않는다.

실측으로 확인한 것 — 이 계정의 Ollama 무료 플랜에서 네이티브 tool calling 이 실제로 성공한 cloud 모델은 세 계열: gpt-oss(20b · 120b) · gemma4(31b) · nemotron-3(nano 30b · super). glm · deepseek · kimi · qwen3.5 · minimax 는 HTTP 402(무료 사용량 미포함). 새 위험: 무료 플랜은 스타터 모델 + 월 단위 소량 크레딧(액수 비공개) + 동시 요청 1 이다 — 상주 비서가 크레딧을 태울 수 있어, m6 은 하루 소모량을 재고 구조는 "모델이 막혀도 산다"를 불변조건으로 갖는다.

v2 에서 바뀐 것 (기록) — 같은 근본원인을 이 문서에 다시 들이댔다

대표의 지적("역할 다섯이 꼭 필요한가, Mark.5 레거시를 너무 많이 받는 것 아닌가")으로 v1 을 다시 봤다. lead 의 자체 검토와 독립 검토(opus)가 구조 요소 37개를 출처로 갈랐다 — 요구 9 · 실측 8 · 레거시 8 · 추측 12. 뒤의 스물은 쓰임이 생기기 전에 판 자리였고, 절반 이상은 Mark.5 가 아니라 조사를 읽고 얹은 것이었다.

§1왜 새로 세우나 — 숫자

Mark.5 를 25일간 실제로 돌린 기록을 읽기 전용으로 쟀다.

자가학습이 멈춘 이유: 세션 파일을 "열린 날" 폴더에 이어 붙이는 코드와 "오늘·어제" 폴더만 읽는 밤 통과가 날짜를 다르게 잡았다. 마지막 폴더는 9월 9일인데 그 안의 파일이 9월 21일까지 218KB로 자랐다. 테스트 566개는 두 모듈의 경계에 있는 이 결함을 못 잡았다.

쓰이는지 재는 자리 없이 장부와 단계를 먼저 늘렸다. 근본원인 한 문장. 구조의 모든 부품을 두 기준에 걸렀다 — ① 사건 장부는 하나 ② 부품마다 산출을 셀 수 있고 "연속 N일 0"이면 경보. 세 번째 — ③ 요구나 실측이 가리키지 않는 자리는 파지 않는다. 단, 비서다움에 직결되는 능력은 한 단계 멀리 보고 v1 에 넣는다(D8).

§2구조를 실제로 떠받치는 원칙

  1. 말하지 않을 조건을 먼저 적는다. 개입 판단은 최신 모델도 40% 안팎이고 Mark.5 의 모델 판정은 30%가 실패했다 — 말할지는 규칙이 정한다. (OpenClaw, PROBE, Mark.5 실측)
  2. 말은 작업이 끊기는 지점에서 건넨다. (CHI 2008 · 2025, Mark.5 전달 상태기계)
  3. 대화 모델은 항상 응답 가능하게 두고, 무거운 일은 독립된 맥락의 작업자가 뒤에서 한다. 그래도 사용자가 도중에 덧붙인 말은 곧바로 반영한다(steer). 작업자는 예산을 함께 쓴다. (Anthropic Research, Hermes Agent)
  4. 기억은 원본 → LLM 이 편집하는 위키. 고칠 때는 전체 재작성이 아니라 작은 추가분만 — 전체 재작성은 18,282토큰이 122토큰으로 붕괴한 실측이 있다. (Karpathy LLM Wiki, ACE)
  5. 기억에 쓸 때 출처를 붙여, 남의 글이 사용자가 말한 사실과 같은 칸에 못 들어가게 한다. 평가하는 쪽에는 모델이 없다. (memory poisoning 연구, Mark.5 gate)
  6. 파일이 진실이고 SQLite 는 색인이다. 개인 규모에 그래프 DB · DB 브랜칭 · 전용 벡터 DB 는 과하다 — SQLite 안의 벡터 표 하나면 된다. (DB 조사)
  7. 도구 검증은 격리 시험 실행과 설명 해시 고정을 함께 써야 한다 — 악성 스킬의 21%가 실행 중 원격 코드를 받아 정적 스캔을 우회했다. (Snyk, Trail of Bits)
  8. 로컬이라고 믿지 않는다 — 무인증 로컬 소켓, 평문 비밀값, 이름 기반 실행 허용 목록이 실제 사고였다. (OpenClaw CVE)

§4결정 D1–D7

대표가 확정한 것만 올렸다. 뒤집는 조건이 없는 결정은 취향이라 싣지 않는다.

D1
새 레포에서 구조를 다시 세우고 Mark.5 모듈을 골라 이식한다
근거 포크해도 코어 2,426줄은 다시 쓰고, 공개하려면 커밋 182개의 히스토리 재작성이 필수다. v2 의 축소로 옮길 실물은 mcp/ · policy · broker · 루프 · 규칙 엔진 · 셸 샌드박스 · gate 패턴 · 하이브리드 색인이다(약 3,300줄).
뒤집는 조건 구획 1에서 이식 모듈의 절반 이상을 다시 써야 하면, 아이디어만 가져오고 새로 쓴다.
D2
자체 하네스 + provider 어댑터. 첫 버전부터 Ollama cloud · OpenAI · Anthropic · Google 등 대부분의 키를 받는다
근거 오픈소스이고 다른 비서도 붙는 규격을 낸다. Claude Agent SDK 는 Claude 전용이고 배포 제품에 구독 로그인 제공이 금지된다. 어댑터는 둘 — OpenAI 호환 하나(OpenAI · Ollama · Gemini 호환 · OpenRouter 류) + Anthropic 네이티브 하나.
뒤집는 조건 특정 provider 가 공통 계약의 통과선을 못 넘으면 "1급 / 실험" 등급으로 나눈다.
D3
v1 = macOS 우선 + 도구 제안 → 승인 → 설치 종단. 서버는 비공개 · 팀원 담당
근거 지원서 1R 시제품과 1차 지표(주 1건 부착)를 재려면 종단이 필요하다. v2 확인 대기 참조 서버 프로세스는 만들지 않고, 연결 규격 문서 + 규격 모양의 시험 자료 + 공식 레지스트리를 직접 읽는 catalog 로 대신한다(§10).
뒤집는 조건 베타 10명 중 비-macOS 가 3명 이상이면 Linux 를 앞당긴다.
D4
설치 대상은 둘 — PATHFINDER 자신의 MCP 클라이언트 + 사용자의 Claude Code 설정
근거 타깃이 실제로 일하는 곳이 코딩 에이전트이고 부착 지표가 거기서 잡힌다. Cursor · Claude Desktop 은 v1 밖.
뒤집는 조건 실측 m5 에서 비파괴 병합 · 롤백이 3/3 을 못 넘으면 v1 은 자신에만 설치한다.
D5
GitHub 비공개 레포로 시작, 이 레포만 noreply 신원. 전체가 돌고 스캔을 통과하면 공개
근거 미완성 구조가 공개 이력에 남지 않고, 라이선스는 법률 자문 뒤 공개 시점에 정한다. 기관 이메일은 커밋에 넣지 않는다.
뒤집는 조건 베타 모집 · 팀원 검토에 공개 링크가 먼저 필요해지면 앞당긴다(라이선스 먼저).
D6
코드 · 주석 · 커밋 · 문서는 영어, README 와 화면은 한 · 영 병행. ARCHITECTURE 는 한국어본을 따로 둔다
근거 공개 오픈소스 + 타 비서 연결 규격. ARCHITECTURE.ko.md 는 대표가 구조를 빠르게 읽기 위한 것.
뒤집는 조건 두 파일이 어긋난 채 2회 이상 커밋되면 한쪽을 정본, 다른 쪽을 생성물로 바꾼다.
D7
유료 API 키 없이 개발 · 검증한다. 도는 모델은 Ollama cloud 모델뿐이다
근거 지금은 API 과금을 할 수 없고, 로컬 모델은 파라미터가 작아 뺀다. 대화 모델은 전부 cloud 이고, 로컬에 남는 것은 임베딩 bge-m3 하나다(대화 모델이 아니다). Claude Code 서브에이전트는 시험 운전자 · 채점자로만 쓴다. Anthropic · OpenAI · Google 직결은 규격대로 쓰고 녹화 응답으로 단위 시험만 하며 "실험" 등급으로 표시한다.
뒤집는 조건 키가 생기면 그 provider 로 m1 을 다시 돌려 "1급"으로 올린다.
D8
원칙 — 문제 해결 도구가 아니라 실질적인 AI 비서다. 항상 한 단계 멀리 본다
근거 대표의 지시. 자르는 기준은 "쓰임이 아직 없다"가 아니라 "없어도 비서 경험이 줄지 않는다"이다.
뒤집는 조건 그렇게 넣은 능력이 실사용 2주에서 한 번도 쓰이지 않으면 §17 로 보낸다.
D9
모델 설정은 model 하나 + 선택 worker_model (+ embed_model). 역할 다섯은 폐기
근거 D7 아래 가격 계층이 없어 역할 넷이 같은 모델에 묶인다. 조건 5 의 "다른 LLM 이 맡는다"는 독립된 맥락으로 성립하고, 다른 모델을 배정하고 싶으면 키 하나로 된다. 모델 ID 는 코드에 없다.
뒤집는 조건 m6 에서 무료 크레딧이 모자라면 가벼운 모델 키를 더한다 — 존재는 확인했다(gpt-oss:20b-cloud · nemotron-3-nano:30b-cloud).
D10
임베딩 · 벡터 색인을 v1 에 둔다 (FTS5 + sqlite-vec)
근거 위키가 자라면 어차피 필요하고, 나중에 넣으면 다시 대처해야 한다. 임베딩은 로컬 bge-m3 또는 provider 의 /v1/embeddings — 같은 호환 어댑터를 지난다. 임베딩이 없거나 죽어도 색인은 FTS 만으로 성공한다(Mark.5 승계).
뒤집는 조건 m4 에서 하이브리드의 recall@3 이득이 FTS 단독 대비 5%p 미만이면 기본값을 끈다(코드는 남긴다).
D11
툴 호출은 네이티브 tool calling 우선
근거 2026-09-22 실측 — 무료 플랜의 세 계열이 OpenAI 호환 엔드포인트로 툴 호출에 성공했다. Mark.5 실측으로 턴의 60%가 1스텝 · 최대 7이라 스크립트 한 장에 호출을 엮는 이점이 작다. 샌드박스는 셸 툴에 남는다.
뒤집는 조건 m1 에서 계열별 85% 미달이면 그 계열은 "실험", 전부 미달이면 코드 모드를 짓는다.
D12
steer 를 v1 에 둔다 — 도는 중에 사용자가 덧붙인 말을 다음 안전한 지점에 반영한다
근거 비서라면 "그거 말고 이걸로"를 도중에 받을 수 있어야 한다. 안전한 지점은 둘 — 툴 호출이 끝난 자리, 또는 답을 쓰는 중이면 스트리밍을 끊고 쓴 데까지를 남긴 자리. 신호는 끼어들지 않고 턴이 끝날 때까지 기다린다(대기 큐 하나).
뒤집는 조건 m2 미달이면 interrupt 뒤 새 턴으로 대신한다.
D13
규칙이 못 정한 신호는 모델에게 묻되 울타리를 친다 — 그리고 이것은 임시다
근거 규칙만으로는 모르는 종류에 영영 말을 걸지 못한다(D8). 울타리: 닫힌 JSON 답 · 하루 20회 · 가벼운 모델 · 매 판단에 👍👎. 구조적 해법의 방향(대표의 단서): 모델 판단은 영구 부품이 아니라 규칙 발견 장치다 — 같은 모양의 판단이 반복되고 👍 를 받으면 정리 통과가 규칙 제안으로 승인함에 올리고, 승인되면 그 종류는 다시 모델에 가지 않는다. 모델 판단 건수가 줄어드는지를 잰다.
뒤집는 조건 2주 뒤 👍 비율이 70% 아래면 끈다. 판단 건수가 4주간 줄지 않으면 규칙 흡수 기제를 다시 설계한다.
D14
참조 서버를 프로세스로 만들지 않는다 (D3 의 문구 수정)
근거 팀원의 서버가 아직 없고, 서면 버릴 코드다. 규격 문서 + 규격 모양의 시험 자료 + 공식 레지스트리를 직접 읽는 catalog.
뒤집는 조건 팀원 서버에 받을 주소가 생기면 주소만 바꾸고, HTTP 왕복 시험과 결과 전송을 그때 함께 넣는다.
D15
작업 맥락과 "CLI 실행" 신호의 출처는 전부 — 화면 붙음 · 셸 훅 · Claude Code 훅. 온보딩에서 하나씩 켠다
근거 맥락의 출처가 없으면 "지금 하시는 작업에 맞는 도구"를 고를 근거가 대화뿐이다. 설치기가 어차피 Claude Code 설정을 다룬다.
뒤집는 조건 2주 실사용에서 어느 출처의 신호가 발화로 한 번도 이어지지 않으면 그 감각을 끈다(Mark.5 의 앱 집중 감각 — 1,274건에 발화 0 — 의 교훈).

§7핵심 루프

  • 트리거는 늘어도 루프는 하나다. 사용자 발화 · 신호 · 게이트 재개 · 작업 완료가 전부 같은 루프를 타고, 다른 것은 봉투와 정책표의 행뿐이다.
  • steer. 도는 중에 사용자가 한 말은 다음 안전한 지점에 끼워 넣는다 — 툴 호출이 끝난 자리, 또는 답을 쓰는 중이면 스트리밍을 끊고 쓴 데까지를 남긴 자리. provider 를 가리지 않는다(메시지 목록에 한 줄을 더할 뿐이다).
  • 대기 큐는 하나. 도는 중에 온 신호는 끼어들지 않고 턴이 끝나면 묶여서 규칙을 지난다. 무거운 일이 작업자로 빠지므로 대화 턴은 설계상 짧다.
  • interrupt 는 실제로 선다. 스트리밍을 끊고 실행 중인 툴을 죽이고 장부에 interrupted 한 줄.
  • 작업자. 대화 모델이 start_job(목표) 을 부르면 독립된 맥락에서 같은 루프가 돈다. 돌아오는 것은 요약 한 덩이와 장부의 작업 구간뿐. 작업자는 작업자를 못 만들고, 하루 예산을 함께 쓴다. 작업자의 정책 행은 signal 과 같다 — 쓰기는 전부 게이트에서 멈춘다.
  • 툴 호출. 네이티브 tool calling. 브로커가 호출마다 인자를 맞추고 정책표로 판정한다.
  • 모델이 막혀도 산다. 크레딧 소진(402) · 한도 · 네트워크 단절에도 데몬은 뜨고, 신호는 장부에 쌓이고, 규칙 발화는 코드가 조립한 문구로 나간다. 막힌 사실은 한 번만 알린다.

§8판정과 말 걸기

말할지는 규칙이 정한다. 규칙은 한 자리(rules.decide)이고 모델 호출이 없다. 알림 문구는 코드가 신호의 칸으로 조립한다(모델이 지어낸 알림은 그대로 사용자에게 간다 — Mark.5 승계). 모델은 그 뒤의 대화를 맡는다.

  • 먼저 거르는 것. 조용한 시간 · 하루 예산 · 신호 턴 사이 최소 30초 · 60초에 5회 넘으면 차단 · 같은 열쇠 24시간 1회. (OpenClaw 의 숫자를 첫 값으로)
  • RULES.md 표. 어휘는 닫혀 있되 감각이 자기 조건어를 등록한다. 감각마다 말하지 않을 조건이 없으면 등록을 거부한다. Mark.5 에서 precision 1.00 이었고 부족한 것은 recall 0.61 — 넓힐 곳이 여기다.
  • 결정은 넷 — speak · silence · defer · ask_model. 규칙이 못 정한 신호는 하루 20회까지 가벼운 모델에게 닫힌 JSON 으로 묻는다(D13). 상한을 넘으면 defer. 매 판단에 👍👎 를 받고, 반복되는 판단은 규칙 제안이 되어 모델을 떠난다.
  • 사용자가 직접 시작한 일의 결말(작업 완료 · 실패)은 하루 예산을 쓰지 않는다 — "끊임없는 대화"가 예산에 막히지 않게 하는 자리다.
  • 전달은 Mark.5 의 상태기계를 승계한다 — 손이 멈췄거나 턴이 끝났을 때만 내려놓는다.

Mark.5 의 2단과 다른 점 — 자유 서술이 아니라 닫힌 답, 상한, 그리고 규칙으로 흡수되어 줄어드는 것이 목표라는 것.

§9기억 — 손이 멈추면 한 번

  • 통과는 하나, 커서도 하나. 손이 멈춘 지 N분이면 장부의 커서 뒤를 읽는다. 커서는 날짜가 아니라 장부의 위치다 — 날짜를 두 곳에서 해석하다 24일을 잃은 종류의 결함이 생길 자리가 없다.
  • 산출은 한 모양. {target, op, old, new, evidence}, 연산은 add · replace · remove 셋. 대상은 wiki/*.md · USER.md · RULES.md. 반복된 절차도 위키의 한 장이다.
  • 평가에는 모델이 없다. gate 가 형식 · 근거의 실존 · 볼트 안인지를 검사하고, USER.md 로 가는 제안의 근거는 origin=user 인 장부 줄만 받는다. 등급은 코드의 기본값 — wiki/ 는 자동 적용(+되돌리기), USER.md · RULES.md · 설정은 승인함.
  • 산출은 장부를 세면 나온다. "읽은 줄 · 낸 제안 · 통과 · 적용"이 전부 사건이다. 읽을 것이 있었는데 3일 연속 산출 0 이면 규칙이 말을 건다. Mark.5 의 24일이 3일이 된다.
  • 검색. 위키 지도(제목과 날짜)가 상주하고, 모델이 search(FTS5 + 벡터를 순위로 합침) 와 read 를 부른다. 임베딩이 없거나 죽으면 FTS 만으로 돈다 — 낡은 벡터는 틀린 값이다.

§10도구 길

  • 연결 규격 v0 (docs/spec/ 에 문서와 시험 자료). 후보마다 name · version · source_registry, 검증 블록(license · malicious_scan · sandbox_trial · maintenance · description_hash · trust_tier), 설치 레시피(런타임 · 고정 버전과 해시 · 환경변수 · 인자 · 권한 요약), 과금 여부 칸. 서버로 돌아가는 결과 칸(proposed · approved · rejected · installed · install_failed)은 규격에 적어 두되 v1 은 보내지 않는다.
  • catalog. 지금은 공식 MCP 레지스트리를 직접 읽어 규격 모양의 후보로 바꾼다. 자기가 실제로 확인한 칸만 채우고 나머지는 not_checked. 팀원의 서버가 서면 같은 모양을 서버에서 받는다 — 바뀌는 것은 주소뿐이다. 능동 제안의 계기: catalog 감각이 하루 한 번 레지스트리의 새 · 갱신된 도구(updated_since)를 확인하고, 최근 작업 맥락의 거친 태그와 맞으면 신호를 낸다. 사용자가 물을 때는 그 자리에서 당겨 온다.
  • 제안. 무엇을 검사했고 결과가 어땠는지를 보여 주고, 안전하다고 말하지 않는다. 검사 기록은 장부에 남는다.
  • 설치기. 런타임 확인(node · uv) → 고정 버전과 해시 대조 → 비밀값은 Keychain → 격리 시험 기동 → 설명 해시 수락(장부에 한 줄) → 설정 비파괴 병합(PATHFINDER · Claude Code) → 실패하면 단계별 롤백. 설치는 승인 게이트 하나를 지난다.
  • 설치 뒤. 설명이 바뀌면 그 툴을 세우고 다시 수락을 받는다(Mark.5 의 핀 기제 승계 — 수락 기록의 자리만 파일에서 장부로).
