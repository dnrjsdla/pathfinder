## 1. Mark.5 진단 — 만든 것 vs 쓰인 것 (25일 실사용)
| 만든 것 | 실측 |
|---|---|
| 감각 4종 + 판정 2단 | 판정 2,239건 → 발화 50건(2.2%, 하루 2회). 23건의 근거가 달력/미리알림 |
| ActivitySense(long_focus) | 1,274건(56.9%) → 발화 0건 |

- 자가학습이 멈춘 원인: 세션 파일을 "열린 날" 폴더에 이어 붙이는 코드와 "오늘·어제" 폴더만 읽는 밤 통과가 날짜를 다르게 잡았다(직접 확인: 마지막 폴더 2026-09-09, 그 안 파일이 09-21까지 218KB). 테스트 566개가 못 잡았다.
- 공개 위생: 커밋 182개 전부 author/committer 가 기관 이메일이고 **전역 git 설정도 같은 주소**. 추적 문서 1곳에 계정 핸들 1건. (Mark.5 를 공개하려면 히스토리 재작성이 필요 — 사용자 결정 사항. 새 레포로 가면 해당 없음.)

**근본원인 한 문장:** 쓰이는지 재는 자리 없이 장부와 단계를 먼저 늘렸다.
→ 새 구조의 두 기준: ① 사건 장부는 하나 ② 부품마다 산출 카운터 + "연속 N일 0" 경보.

## 2. 조사에서 건진 원칙
1. 턴 중에 온 신호는 steer(끼워 넣기) / collect(모으기) / followup(끝난 뒤) 로 처리 (OpenClaw, Codex)
2. 말 걸기는 Notify / Question / Review 셋 — 뒤의 둘만 멈춰서 기다림 (LangChain ambient agents)
3. 말하지 않을 조건을 먼저 적는다. 개입 판단은 최신 모델도 40% 안팎 → 규칙 게이팅 병행 (OpenClaw, PROBE)
4. 말은 작업이 끊기는 지점에서 (CHI 2008·2025)
5. front 모델은 항상 응답 가능, 무거운 일은 독립 맥락의 worker 가 백그라운드에서, 개시·완료가 다시 신호로. worker 공유 예산 상한 (Anthropic Research, Hermes)
6. 기억 = 원본 / LLM 이 편집하는 위키 / 스키마 3계층. 갱신은 전체 재작성 말고 작은 추가분만(전체 재작성은 18,282→122 토큰 붕괴 실측) (Karpathy LLM Wiki, ACE)
7. 기억에 쓸 때 출처를 붙인다 — 남의 글이 사용자 사실과 같은 칸에 못 들어가게 (memory poisoning 연구). Mark.5 의 결정론 게이트+승인함은 업계가 수렴 중인 방향
8. 저장 = JSONL 원본 + markdown + SQLite 색인이 2026년 표준. Ollama → fastembed(pip 만)로 설치 마찰 감소
9. 도구 검증 = 격리 시험 실행 + 설명 해시 고정 병행(악성 스킬 21%가 실행 중 원격 코드로 정적 스캔 우회) (Snyk, Trail of Bits)
10. "미설치 도구를 작업 맥락에 맞춰 먼저 추천 + 검증 + 설치"를 묶은 시스템은 없다 — 지원서의 빈자리가 조사로도 확인됨

## 3. 구조 제안
```
신호원 ── CLI 실행 · 메일 · 일정 · 백그라운드 작업 개시/완료/실패 · 특이점 · 서버의 새 검증 도구
   │        (감각 = 플러그인 한 파일 + 등록부 한 줄)
   ▼
[사건 장부 하나]  append-only JSONL = 진실 · SQLite = 색인+대기 상태(빈 DB에서 복원)
   ▼
[판정]  0단 침묵조건·rate limit → 1단 규칙(비용 0) → 2단 작은 모델 → Notify / Question / Review
   ▼
[대화 lane 하나 — front 모델, 스트리밍 · interrupt]
   · 턴 중 신호: steer / collect / followup
   · 무거운 일 → worker 작업 개시 → lane 은 즉시 응답 가능
   · 쓰기·설치 → 승인 게이트(재시작에도 살아남음)
   ▼                                  ▲
[worker들 — 강한 모델, 독립 맥락, 공유 예산]──완료·실패가 신호로 복귀
   ▼
[밤]  싼 모델이 추출 → 강한 모델이 위키 승격·모순 해소 → 결정론 게이트 → auto / 승인함
      단계마다 산출 카운터, 연속 N일 0 이면 경보
[도구 길]  맥락 → 거친 태그만 서버로 → 검증된 후보 → 로컬에서 순위 → 제안(검사 결과 표시)
          → 승인 1회 → 설치기(런타임 확인 · 비밀값은 Keychain · 설정 비파괴 병합 · 해시 고정 · 롤백)
          → 결과만 서버로(내용 없이, 옵트인)
```

**Claude Code 안의 개발팀** (대표 = 사용자, lead = 메인 세션)
- architect(fable, 설계만) · researcher(sonnet) · implementer(sonnet, worktree) · senior-impl(opus, worktree) · reviewer(opus, 읽기 전용) · qa(sonnet). 전부 `effort: high`, `.claude/agents/*.md` 로 고정.
- 흐름: 계획 → 대표 승인 → 구현 → 검증 → 개인정보 스캔 → 커밋.
- experimental "agent teams" 는 lead 가 계획을 자동 승인해 대표 승인 자리가 없으므로 쓰지 않음.
- `.claude/settings.json` 권한 설정은 승인 전에는 넣지 않음.

## 4. 갈림길 — 열린 결정 셋
**Q1. 기반**
- (a) **새 레포 + Mark.5 모듈 선별 이식 (권고)** — 그대로 ≈2,250줄(`brain/mcp/`, `policy.py`, `react.py`+`broker.py`, gate 등급표 패턴) + 고쳐서 ≈1,200줄(`gateway/`, `rules.py`, `index.py`). 대가: daemon·turn·night·감각·tui 새로 작성, 테스트 대부분 새로.
- (b) Mark.5 포크 후 개명 — 대가: 코어 2,426줄은 어차피 재작성, 한글 섞인 줄 26.7%, macOS 호출지점 55곳, 공개하려면 히스토리 재작성 필수.
- (c) 이식 없이 완전히 새로 — 대가: 검증된 MCP 클라이언트 1,858줄과 주입 방어 실측(0/20)을 버림.

**Q2. 런타임(LLM 층)**
- (a) **자체 하네스 + provider 어댑터 (권고)** — Anthropic 먼저(스트리밍·네이티브 tool calling·캐시), 사용자는 본인 API key. 대가: 루프·권한·세션·맥락 관리를 직접 구현.
- (b) Claude Agent SDK 위에 — 루프·훅·서브에이전트·샌드박스를 바로 얻음. 대가: Claude 전용, wheel ≈100MB + 세션당 ≈1GiB, 정책상 배포 제품은 구독 로그인 제공 불가(API key 만), "Claude Code" 명칭 불가. 오픈소스·타 비서 연결이라는 지원서 서술과 충돌.
- (c) (a) 기본 + worker 백엔드로 Agent SDK 선택 설치 — 대가: 실행 경로가 둘.
- 어느 쪽이든 도메인 도구를 MCP 서버 형태로 짜 두면 (a)↔(b) 이동 비용이 최소.

**Q3. v1 범위**
- (a) **macOS 우선 + 도구 제안→승인→설치 종단 포함 (권고)** — 서버는 비공개·팀원 담당이므로 이 레포에는 연결 규격 문서 + 공식 MCP 레지스트리를 읽는 테스트·데모용 참조 서버만(검증 규칙 제외). 대가: Linux/Windows 는 v1 불가, 팀원과 규격 합의 필요.
- (b) macOS + Linux 동시 — 대가: 샌드박스·알림·감각 두 벌. 실수요 미확인.
- (c) 비서 코어만, 도구 길은 다음 — 대가: 1R 시제품의 핵심과 1차 지표를 잴 수 없음.
